## 一、硬件事实(全部有出处,不是推的)

出处:厂商原理图 `ESP32-S3-0.96LCD`(PDF)+ 厂商 Arduino demo
(`Arduino/lib/TFT_eSPI`、`examples/250428/GIF/Animation`)。

| 项 | 事实 | 出处 |
|---|---|---|
| 面板 | ST7735S,**GREENTAB160x80**,竖屏 80x160 | 原理图 C5「0.96 inch LCD ST7735S」;demo `User_Setup.h` |
| 接口 | SPI,**MODE0**,**只写**(模块不接 MISO) | demo `TFT_SPI_MODE=SPI_MODE0`、`TFT_MISO=-1` |
| 引脚 | SCLK=**GPIO10**、MOSI=**GPIO11**、CS=**GPIO12**、DC=**GPIO13**、RST=**GPIO14** | 原理图 C5 pin3/4/5/6/7 ↔ U1 GPIO11/10/13/14/12 |
| GRAM 偏移 | 竖屏 colstart=**26**、rowstart=**1**;横屏 1/26 | demo `ST7735_Rotation.h`(GREENTAB160x80 分支) |
| 颜色序 | 面板是 **BGR** ⇒ MADCTL 的 BGR 位(0x08)置 1,像素按 RGB565 原样发 | demo `TFT_RGB_ORDER=TFT_BGR` + `TFT_MAD_COLOR_ORDER` |
| 背光 | **没有控制脚**。LEDK(pin11)经 **R2=10Ω 直接接地**,阳极在模块 VCC ⇒ **背光常亮、亮度固定、既不能调也不能关** | 原理图 C5 pin11 + R2 |
| 板上 LED | 原理图上**没有 LED 器件** ⇒ 这块板**没有状态灯** | 原理图全图 |
| microSD | 原理图上有 TF-SD 卡座(TF1),GPIO47=SD_CMD、GPIO48=SD_D3 —— **板上是否贴片未确认** | 原理图 |
| SPI 主机 | 用 **SPI2_HOST(FSPI)**。N16R8 是**八线 PSRAM**,S3 上 flash+PSRAM 占的是 SPI0/SPI1,SPI2/SPI3 留给外设 | IDF `mspi_timing_config.c`(esp32s3) |

### 背光这一条为什么重要

它不是"选哪个 GPIO"的问题,是**这块屏在物理上一定会亮**:
插上电、面板 VCC 有电,背光就亮,亮度由 R2 定死。**固件改不了它。**

⇒ 想让屏"看起来是灭的",唯一手段是**把画面刷成全黑**(面板不显示内容,但背光仍在,
远看是一块暗色玻璃,不是一块发亮的屏)。

⇒ 顺带解释了一件怪事:**厂商 Arduino demo 里 `TFT_BL` 整行是注释掉的**
(`//#define TFT_BL PIN_D1`)—— 因为板上**根本没有可写的 BL 脚**。

## 二、它动摇了什么(与 2026-10-25 初稿的差别)

1. **"无痕"**(output-channel-design.md §八验收项)——
   初稿写的是"屏默认全黑/息屏,只有被注入时才亮"。
   **现在这条不成立了**:背光常亮,屏插上就在那儿。
   诚实的说法变成:**"可察觉"** —— 设备在物理上是看得见的,这与
   "磁盘无残留、拔线 5s 进程退出"是两件事(后者仍然成立)。

2. **"设备端只搬运,不解读"(哑设备原则)**——
   屏是**输出通道**,不是数据通道。显示目标机画面 ⇒ 设备要解 JPEG + 缩放 + 刷屏。
   不违反哑设备原则,但必须写清它是"输出"。

3. **"屏替代 LED"(角色 A)失去前提** ——
   原理图上没有 LED。**这块屏是板上唯一的可视输出**,
   它的价值不取决于"要不要替代 LED"。

## 三、三个角色重新裁剪后

| 角色 | 屏上显示什么 | 设备端要做什么 | 前置工程量 | 关键卡点 |
|---|---|---|---|---|
| **A. 状态显示** | 就绪/忙/故障/网络状态 | 画状态码(已有 `io_led_state()` 的 int)+ 一个点阵字库 | **小**(~1 KB 字库 + 几百行) | 没有 LED 可替代 ⇒ 只能"更好看的 LED";文字只能是 ASCII(80x160 放得下 16 列 × 8 行) |
| **B. 随身看目标机画面** | 目标机画面的缩略图 | 读盘找最新帧 → **解 JPEG** → 缩放 → 刷屏 | **中** | ① **别在设备上解全分辨率**:1080p 的 RGB565 中间缓冲是 2 MB,解码也慢 ⇒ **缩放必须在目标机做**(watcher 顺手多写一张 160x80 的小图),设备只解小图 ② 解码器已有现成的:厂商 demo 里带着 **picojpeg**(MIT,~3 KB);IDF 5.5.6 另有 `esp_driver_jpeg` ③ **80x160 看不清字** —— 只能"看出个大概布局",认得出"有个对话框"就不错了 |
| **C. agent 侧回显** | agent 正在做什么 / 刚做完什么 | 新增一个 MCP 工具(agent 推文字下来)+ 字库 | **小~中** | **需要一条 agent → 设备的下行消息通道**:现在设备只回状态码(int),不回自由文本 ⇒ 要么加 MCP 工具,要么让 `status` 带上"最近一次动作"的描述字段 |

### 数据源现状(决定了 B 和 C 的成本)

- **B 的数据通路已经有了**:设备本来就在读 RAM disk 找最新帧(`io_disk` + mtime 排序),
  目标机上 watcher 已经在写帧。**只要让 watcher 多写一张小图,链路不用改拓扑。**
- **C 的数据通路差一截**:设备现在能算状态码(int),但没有"agent 说的一句话"这种自由文本。

## 四、建议的推进顺序

1. **先做 C 的最小版**:加一个 MCP 工具让 agent 能往屏上写一行 ASCII 文字。
   成本最小、信息密度最高(80x160 恰好够显示一行提示 + 状态),
   而且它让屏**在有 agent 在干活的时候有用**,不依赖目标机额外配置。
2. **再做 B**:watcher 多写一张 160x80 缩略图(缩放在目标机做,设备只解小图),
   设备端加一个"读盘 → picojpeg → 刷屏"的后台任务。**这一条让屏在没有 agent 在场时也有用。**
3. **A 不单独做**,它是 C 的子集(状态码也能用 C 的通道写上去)。

## 五、已经拍板的事(2026-10-25 用户定调)

| 问题 | 决定 |
|---|---|
| 屏上要不要中文 | **不要**。屏只有 160x80,中文字模要几十 KB flash,而且 0.96 寸上 16x16 汉字几乎看不清 ⇒ 只做 ASCII(6x8 格子,26 列 × 10 行) |

## 六、驱动与内容层现状

### 驱动(`firmware/io_lcd/`)

- ST7735S 驱动,编译期开关 `CONFIG_SOPHON_LCD_ST7735`(量产固件已打开,见
  `firmware/sdkconfig.defaults`)
- **画布在 PSRAM**(160x80x2 = 25.6 KB),面板是"只写终端" ⇒ 典型用法是
  往画布画 → `io_lcd_flush()` 推一次。上层(JPEG 缩略图、文字)用普通 2D 画布 API
  就行,不用每画一个像素发一次 SPI
- 行缓冲 320 字节放**内部 RAM**(SPI DMA 要能访问),画布在 PSRAM(八线 PSRAM
  的 SPI DMA 能不能直接吃 PSRAM 不去赌)
- flash 开销:`libio_lcd.a` 约 3 KB + 字库 475 字节
- 开机流程:彩条自检 3 秒 → 常驻信息屏(`SOPHON` + 设备 IP)

### ★ 踩过的两个坑(都是"编译过了、事务全成功,但屏是死的")

1. **初始化表抄残了 —— 面板从来没被打开过**。
   厂商 TFT_eSPI 的 `ST7735_Init.h` 里,GREENTAB160x80 走的是
   `Rcmd1 + Rcmd2green + INVON + Rcmd3` 四段;而 **NORON(0x13) 和 DISPON(0x29)
   在 Rcmd3 里**,Rcmd3 最容易被漏抄 ⇒ SPI 全部成功、驱动自检也报"画完了",
   **但屏是全黑的、什么图案都没有**。
   ⇒ 判定"驱动跑通了"**不能只看 SPI 返回值,屏上有没有东西才算数**。
2. **厂商那份 glcdfont.c 的字符顺序不是线性的**。它写着
   "Original Adafruit_GFX 5x7 font",但实测字形 33 是 `'!'`、字形 35 是 `'H'`,
   按 ASCII 顺序索引会取到完全错的字形 ⇒ 自己用 PIL 光栅化生成
   (`tools/gen_font5x7.py`,Tahoma 48 px → BOX 降采样 → 5x7,bit0 = 最上面一行),
   顺序天然正确,还能先把预览图渲染出来**用眼睛验**。

### 内容层(C 最小版,已落地)

- **点阵字库**:`firmware/io_lcd/font_glcd5x7.c`(95 个可打印 ASCII,475 字节)
- **MCP 工具 `screen { text }`**:agent 把一段 ASCII 推到屏上。
  这是设备第一次能收"自由文本"——原来它只能回状态码(int)。
  实测:契约探针 **28/28** 全过,`{"ok":true,"lines":3}`
- 屏朝向人 ⇒ 它的用途是"**站在目标机前面的人,不用看聊天就知道 agent 在干什么**"

### 下一阶段(B:目标机画面缩略图)

- 缩放**必须在目标机做**:watcher 顺手多写一张 160x80 的小图,
  设备端只解小图(picojpeg,厂商 demo 里现成有,MIT)。
  在设备上解 1080p 是 2 MB 中间缓冲 + 解码时间,不值当。
- 画布 API 已经就位(`io_lcd_fb()` + `io_lcd_flush()`)⇒ 内容层只要把
  解码结果画进画布就行。
