# watcher/ — 目标机侧驻守程序(零安装)

跑在目标机上的采集/执行体。**进程级运行,不落盘、不注册服务、不建计划任务**;
拔掉设备后应自行退出(写盘失败自检触发)。

载体是 ESP32 的 RAM disk(虚拟 U 盘),盘符不固定 → **一律自扫可移动盘 + 按卷标定位**,
不要硬编码 `X:`。

## 职责

1. **启动**:被 ESP32 用 HID 注入 `Win+R` → `powershell -ExecutionPolicy Bypass -File <盘>\watch.ps1` 拉起。
2. **采集**:截图 + JPEG 编码 + 写盘。采集封装为独立层,便于后续把 GDI 换成
   DXGI Desktop Duplication(一代定案用 GDI,见 `docs/design-review.md` 结论 1)。
3. **写盘**:双缓冲 `SNAP_P/SNAP_A` + `SNAP.IDX`(序号两次一致才取帧,防 FAT 撕裂);
   变化 ROI 写 `DIFF.IDX`;命令 `CMD\*.cmd` → 结果 `RESP\*`。
4. **执行**:按 `CMD` 执行读文件 / 跑命令 / 网络请求,结果回写 `RESP`。
5. **自检退出**:写盘失败(盘消失)→ 判定载体丢失 → **主动退出**,不残留进程。
6. **能力自陈**:启动后写 `CAP.TXT`(os/arch/admin/net/screen/watcher_ver)。

## 分层快照(带宽关键,别改回连续全帧)

- 预览帧:**2fps**、降采样 960×540、quality 70(约 40-60KB/帧)常驻。
- 变化 ROI:分块(16×16)哈希比较定位变化区,只写变化区 JPEG。
  **不要在 PowerShell 里逐像素比对 1080p**——性能黑洞。
- 全分辨率帧:仅当收到 `CAP_FULL` 时抓一次(约 300KB),不常驻。
- 禁止 1080p×5fps 连续全帧写盘:1.5MB/s > MSC 实测 1MB/s 上限,会饿死 CMD/RESP。

## 截图里要带光标(否则 agent 不知道鼠标在哪)

GDI `CopyFromScreen` **不包含鼠标指针**(光标是独立覆盖层)。
必须:`GetCursorPos` 取光标坐标 → **在截图上合成光标标记**,并把光标坐标写进
`SNAP.IDX` 随帧返回。
否则 agent 看到的是一张"没有光标的屏幕",会误判成点击偏移而反复瞎试。

**标记必须是实心圆点,不能是空心环。** diff 用 16×16 块哈希 + 块内稀疏采样定位变化,
空心环缩放到预览尺寸后只剩 ~1px 描边,采样点全部落在环外 → 块哈希不变 → 鼠标明明
动了却报"画面无变化"。实心圆点直径十几像素,必有采样点命中。

**X/Y 缩放比例要分开算。** 预览固定 960×540,而被截的桌面可以是任意宽高比,
两个轴的比例不同;共用一个比例会把标记放偏。
**不要把屏幕尺寸写死**:运行时用 `SystemInformation.VirtualScreen` 现取。
(实测本机是 800×600 / 4:3,不是 16:9 —— 也就是说预览 960×540 是**非等比拉伸**,
两个轴的比例分别是 1.2 和 0.9。这在几何上是自洽的(见下节),但画面会变形。)

## ROI 坐标在哪个空间(消费方必须知道)

diff 跑在**预览图**(960×540)上,块哈希网格是 60×34(块 16px,最后一行钳到图高)。
变化块合并成矩形后,像素坐标仍属**预览空间**。
但写进 `SNAP.IDX` / `DIFF.IDX` 的 `rects` 是**全分辨率空间** —— 代码在写盘前用
`scaleX = full.Width / 960`、`scaleY = full.Height / 540` 把预览矩形映射回抓屏原图,
再从**全分辨率**位图裁出 `SNAP_R.JPG`。

所以:

- `SNAP.IDX` 的 `cursor` 是**全分辨率**坐标(直接来自 `GetCursorPos`)。
- `SNAP.IDX` / `DIFF.IDX` 的 `rects` 是**全分辨率**坐标,与 `SNAP_R.JPG` 的裁剪区域同空间。
- 两者**不是**预览坐标。要在预览上画框,得自己除回 scaleX/scaleY。

实测核对(2026-10-24,800×600 桌面):`DIFF.IDX` 的 7 个矩形取包围盒得
(320,266)–(747,551) = 427×285,与落盘的 `SNAP_R.JPG` 像素尺寸 **427×285** 精确吻合。

两个边界钳制也核过,不会出界:
- `Get-BlockHashes` 用 `yMax = Min(y0+Block, Height)-1` 夹住最后一行
  (34 行 × 16 = 544 > 540,不会越界读);
- `Get-RoiBytes` 对包围盒做 `Min` 钳制,裁不出图。
- 注意:`SNAP.IDX` 里的**单个** rect 没做钳制(只有包围盒钳了),
  落屏底边时单个 rect 可能超出画面几个像素 —— 消费方按 rect 定位时留个余量。

## diff 采样约束(改动前先读)

- 块内采样步长 ≤ **3**(4 会漏掉细描边,见上)。
- 变化块合并成矩形时,合并条件要跟矩形的**结束行**比,并同步更新结束行。
  跟**起始行**比会导致矩形永远只有 1 块高,纵向连续变化被碎成一片 1 行条。
- 自检:`tests/test_watcher_diff.ps1` 用合成图验证三件事(相同帧无输出、光标圆点
  必被检出、跨行竖条必须合并成一个高矩形),不依赖真实鼠标,不会被人工操作干扰。

## 与设备端的配合

- 帧是**给设备端拉取**的:agent → 设备 → 读盘 → 直传。设备不主动推,所以脚本必须
  **持续写预览帧**(2fps),并保证 `SNAP.IDX` 的序号可靠前进——设备靠序号前进来判断
  "有新帧",并据此满足 capture 的新鲜度要求。
- 脚本不需要知道 agent 在哪、不需要出网,只管把帧写到盘上。

## 编码注意

- PowerShell 5.1(Windows 自带)是目标基线,不要用 PS7 专属语法。
- 隐藏窗口运行;不产生控制台闪烁。
- 脚本语言保持 ASCII 固定路径与协议;面向用户的提示文案按目标机 locale 选择
  (zh-Hans / en),不硬编码。
- 避开杀软敏感特征,不与 EDR 对抗(强管控环境视为一代适用范围之外)。
