# watcher/ — 目标机侧驻守程序(零安装)

跑在目标机上的采集/执行体。**进程级运行,不落盘、不注册服务、不建计划任务**;
拔掉设备后应自行退出(写盘失败自检触发)。

载体是 ESP32 的 RAM disk(虚拟 U 盘),盘符不固定 → **一律自扫可移动盘 + 按卷标定位**,
不要硬编码 `X:`。

## 职责

1. **启动**:被 ESP32 用 HID 注入 `Win+R` → `powershell -ExecutionPolicy Bypass -File <盘>\watch.ps1` 拉起。
2. **采集**:截图 + JPEG 编码 + 写盘。采集封装为独立层,便于后续把 GDI 换成
   DXGI Desktop Duplication(一代定案用 GDI,见 `docs/design-review.md` 结论 1)。
3. **写盘**:双缓冲 `SNAP_P/SNAP_A` + `SNAP.IDX`(序号两次一致才取帧,防 FAT 撕裂);
   变化 ROI 写 `DIFF.IDX`;命令 `CMD\*.cmd` → 结果 `RESP\*`。
4. **执行**:按 `CMD` 执行读文件 / 跑命令 / 网络请求,结果回写 `RESP`。
5. **自检退出**:写盘失败(盘消失)→ 判定载体丢失 → **主动退出**,不残留进程。
6. **能力自陈**:启动后写 `CAP.TXT`(os/arch/admin/net/screen/watcher_ver)。

## 分层快照(带宽关键,别改回连续全帧)

- 预览帧:**2fps**、降采样 960×540、quality 70(约 40-60KB/帧)常驻。
- 变化 ROI:分块(16×16)哈希比较定位变化区,只写变化区 JPEG。
  **不要在 PowerShell 里逐像素比对 1080p**——性能黑洞。
- 全分辨率帧:仅当收到 `CAP_FULL` 时抓一次(约 300KB),不常驻。
- 禁止 1080p×5fps 连续全帧写盘:1.5MB/s > MSC 实测 1MB/s 上限,会饿死 CMD/RESP。

## 截图里要带光标(否则 agent 不知道鼠标在哪)

GDI `CopyFromScreen` **不包含鼠标指针**(光标是独立覆盖层)。
必须:`GetCursorPos` 取光标坐标 → **在截图上合成光标标记**(十字/圆环),
或把光标坐标写进 `SNAP.IDX` 随帧返回。
否则 agent 看到的是一张"没有光标的屏幕",会误判成点击偏移而反复瞎试。

## 与设备端的配合

- 帧是**给设备端拉取**的:agent → 设备 → 读盘 → 直传。设备不主动推,所以脚本必须
  **持续写预览帧**(2fps),并保证 `SNAP.IDX` 的序号可靠前进——设备靠序号前进来判断
  "有新帧",并据此满足 observe 的 `max_age_ms` 新鲜度要求。
- 脚本不需要知道 agent 在哪、不需要出网,只管把帧写到盘上。

## 编码注意

- PowerShell 5.1(Windows 自带)是目标基线,不要用 PS7 专属语法。
- 隐藏窗口运行;不产生控制台闪烁。
- 脚本语言保持 ASCII 固定路径与协议;面向用户的提示文案按目标机 locale 选择
  (zh-Hans / en),不硬编码。
- 避开杀软敏感特征,不与 EDR 对抗(强管控环境视为一代适用范围之外)。
